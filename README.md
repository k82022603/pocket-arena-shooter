# Arena Shooter — 모바일 웹 2인 근거리 슈팅 게임

『파이브 스타 스토리』의 파티마를 조종하는 탑다운 트윈스틱 슈터. 설치 없이 브라우저만으로 실행하고, 같은 Wi‑Fi에 있는 두 사람이 QR을 한 번 찍어 1:1 대전이나 협동 방어전을 한다. 게임 데이터는 서버를 거치지 않고 두 기기가 직접 주고받는다.

> **팬 게임 정책** — 나가노 마모루의 『파이브 스타 스토리』 2차 창작이며 **비수익**으로만 운영한다. 앱스토어·공개 웹 배포, 광고·결제·후원, 공개 랭킹, 행사 비치를 하지 않는다. 코드 저장소는 공개이지만 **원작 일러스트는 저작권 때문에 포함하지 않았고 커밋 이력에서도 지웠다.** 초상 카드를 보려면 이미지를 직접 넣어야 하며([방법](apps/web/public/fatima/README.md)), 없어도 게임은 정상 동작한다.

## 빠른 시작

```bash
npm install
```

서버 두 개를 함께 띄우고 폰에서도 접속 가능한 **LAN 주소**로 브라우저를 연다. Windows는 `play.cmd` 더블클릭도 같다.

```bash
npm run play
```

터미널에 `게임 주소: http://<노트북 IP>:5173/` 가 찍힌다. 폰을 같은 Wi‑Fi에 붙이고 그 주소를 열면 된다. `localhost`는 폰 자신을 가리키므로 폰에서는 열리지 않는다. 주소는 Wi‑Fi를 옮기면 바뀌므로 매번 터미널 출력을 본다.

`localhost`로 열어도 **방 만들기 QR에는 개발 서버가 찾은 LAN 주소가 들어간다.** QR 아래에 실제 주소가 표시된다.

폰의 카메라로 QR을 스캔하는 기능은 secure context가 필요하므로 https로 띄운다. 자체 서명 인증서 경고는 한 번 수락한다.

```bash
npm run play -- https
```

## 구조

```
apps/web                 Vite + TypeScript + Phaser 3 클라이언트
  src/sim                순수 TS 시뮬레이션 (60Hz 고정 틱, 결정적 로직, 시드 PRNG, 바이너리 직렬화)
  src/net                Transport 인터페이스, WebRTC DataChannel, WebSocket 릴레이, 시그널링, 재접속
  src/game               Phaser 씬(Boot/Title/Lobby/Arena/Result), 동기화 구현, 입력, 연출, 오디오
apps/signaling           Node + ws 시그널링/릴레이 서버 (6자리 방 코드, SDP/ICE 중계, 바이너리 릴레이)
packages/protocol        클라이언트·서버 공용 시그널링 메시지 타입
scripts                  LAN 실행, 헤드리스 검사, 아이콘 생성
docs                     기획서, 매뉴얼, 테스트 가이드, 회고
```

계층 규칙은 하나다. **`sim/`은 Phaser도 DOM도 네트워크도 모른다.** 그래서 같은 코드가 브라우저·Node·호스트·게스트 예측에서 그대로 돌아가고, 화면 없이 검사할 수 있다. 의존 방향과 파일 지도는 [개발자 매뉴얼](docs/06.개발자_매뉴얼.md) 4장과 9장에 있다.

## 게임

- 파티마 4종(라키시스/클로소/아트로포스/에스트). 이동속도·HP·탄 위력·연사·대시가 서로 다르고, 게임 크기에서 구별되도록 실루엣을 나눴다
- 기본 무기를 파티마마다 3종 중 고른다. 플레임 런처 / 니들 스트림 / 버스터 런처 / 스캐터 건. 선택은 기기에 저장되고 캐릭터 패킷으로 상대에게 전달된다
- **게임 중 교체 가능.** PC는 `1`~`3` 키, 모바일은 우측 무기 버튼 탭으로 순환. 교체 직후 0.3초 발사 불가. 픽업 무기를 들고 있으면 픽업이 끝난 뒤 적용된다
- 아레나 픽업은 15초마다 최대 3개. 리페어 팩 40%, 스캐터 캐논 25%, 레이저 랜스 20%(관통), 이레이저 부스트 15%
- **혼자 하기와 난이도** — 타이틀의 혼자 하기 옆 **하·중·상**으로 고르고 기기에 저장된다. 대전에서는 봇의 솜씨(조준 오차, 대시 회피 확률, 점사 간격, 앞질러 쏘기)가, 방어전에서는 적의 수가 바뀐다. 둘이 하는 경기는 난이도와 상관없다
- **1:1 대전** — 상대 HP를 먼저 0으로. 혼자 하기에서는 봇이 붙는다. 거리 유지·좌우 왕복·픽업 줍기·날아오는 탄 대시 회피·오차 있는 조준·점사를 한다
- **협동 방어전** — 중앙 코어(HP 500)를 지키며 10웨이브의 적을 전부 처치하면 승리. 10웨이브 합계 175기, 0.67초 간격으로 한 기씩 네 변에서 등장. 척후병·포수·강습병 3종이고 **포수의 유탄은 코어를 8씩 깎는다.** 다운된 아군 곁에 2초 머물면 50% HP로 부활하며 혼자 하기에는 부활이 없다. 아군 피해 없음. **1인 방어는 적 편성이 난이도에 따라 하 53기 / 중 77기 / 상 116기이고 픽업이 9초마다** 나온다. **적에게 닿으면 뒤로 밀려난다**(척후병·포수 약 40px, 강습병 약 60px, 대시 중에는 피해도 넉백도 없음). 자동 플레이 클리어율은 1인 하 78% / 중 53% / 상 15%, 2인 68%

## 조작

- **모바일** — 왼쪽 절반 드래그로 이동, 오른쪽 절반 드래그로 조준하고 30% 이상 밀면 자동 연사, `DASH` 버튼, 무기 버튼
- **PC** — WASD 또는 방향키 이동, 마우스로 조준, 왼쪽 버튼 홀드 발사, `Shift`/`Space` 대시, `1`~`3` 무기. 키보드나 마우스를 쓰는 순간 켜지며 점선 조준 가이드와 레티클이 나타나고, 터치를 쓰면 스틱으로 돌아간다. 협동과 봇 상대 대전에는 **조준 보정**(조준 방향 앞 18도 안의 적에게 붙여 쏨, 타이틀에서 켜고 끔)이 있고, 사람끼리의 대전에는 없다. 키는 물리적 위치(`event.code`)로 읽어 **한/영 상태와 상관없이** WASD가 먹는다. 키보드 입력이 게임 밖(주소창·다른 창)에 가 있으면 화면 아래에 안내가 뜬다

## 2인 연결

방 만들기를 누르면 참가 링크 QR과 6자리 코드가 나온다. 참가 경로는 세 가지다.

1. 폰 기본 카메라로 QR을 찍어 링크로 열기
2. 앱 안 QR 스캐너 (Chrome은 `BarcodeDetector`, 그 외는 jsQR 폴백, https 필요)
3. 6자리 코드 직접 입력

QR이나 링크로 들어와도 타이틀에서 파티마와 무기를 고른 뒤 입장한다. 초대 코드는 세션 저장소에 남아 탭을 새로고침해도 다시 묻지 않는다.

연결은 WebRTC DataChannel 두 개를 쓴다. `input`은 순서·재전송 없이 지연 우선, `event`는 순서 보장 신뢰 우선이다. 5초 안에 P2P가 붙지 않으면 양쪽이 합의해 WebSocket 릴레이로 내려간다.

블루투스 모드는 없다. 모바일 브라우저는 폰끼리 블루투스로 직접 연결할 수 없다. 이유는 [연결 방식 문서](docs/03.연결_방식_블루투스_대신_WiFi.md)에 정리했다.

## 동기화

호스트 권위 모델이다. 방을 만든 쪽이 양쪽 입력으로 시뮬레이션을 돌리고 20Hz로 월드 전체 스냅샷을 보낸다. 참가한 쪽은 지연을 감추기 위해 다섯 가지를 함께 쓴다.

- **예측** — 자기 입력을 응답 없이 즉시 적용한다. 체감 지연 0
- **재조정** — 스냅샷의 확인 틱을 기준으로, 아직 확인되지 않은 입력만 다시 적용해 현재를 재구성한다
- **보간** — 상대·탄환·적은 100ms 과거를 보여주고 두 스냅샷 사이를 잇는다
- **되감기 판정** — 호스트가 게스트 탄환을 판정할 때 쏜 사람이 본 시점의 위치로 표적을 되감는다. 상한은 모드별로 다르다. **대전 200ms**(표적이 사람이라 "엄폐한 뒤에 맞았다"를 막아야 한다), **협동 400ms**(표적이 AI라 그 제약이 없다). 협동의 적도 되감으며, 적은 수가 변하고 id가 웨이브마다 새로 발급되므로 링 버퍼에 id를 함께 적는다
- **보정 스무딩** — 재조정으로 권위 위치가 예측과 달라도 화면에서 순간이동하지 않는다. 상태는 권위대로 덮고 차이만 화면 오프셋으로 들고 있다가 70ms 반감기로 0에 수렴시킨다. 판정과 탄환 생성은 항상 권위 위치를 쓰므로 명중에 영향이 없다. 96px를 넘는 어긋남은 미끄러뜨리지 않고 즉시 붙이고, 오프셋은 48px로 제한한다

게스트 입력은 60Hz로 보내며 패킷마다 직전 2틱을 중복 포함해 손실을 복구한다. 발사도 예측하며, 탄환에 실린 발사 입력 틱으로 권위 스냅샷의 탄환과 대조해 인정되지 않은 예측 탄은 지운다.

**재접속** — 서버가 끊긴 슬롯을 15초간 토큰으로 보존하고, 클라이언트는 10초 안에 시그널링을 다시 붙여 재입장한다. 그동안 호스트는 시뮬레이션을 멈추고 양쪽에 재연결 안내를 띄운다. 복구되면 호스트가 캐릭터와 스냅샷을 신뢰 채널로 재전송하고 끊긴 지점부터 이어간다. 실패하면 남은 쪽 승리, 협동은 패배로 결과 화면에 간다.

측정값과 바이트 레이아웃은 [개발자 매뉴얼](docs/06.개발자_매뉴얼.md) 6장과 7장에 있다.

## 화면과 모바일 대응

- **화면 크기에 맞춘 UI 배율.** 폰 가로 844×390을 기준 1로 두고 글자·버튼·간격에 배율을 곱한다. 큰 화면에서는 늘어난 만큼의 절반만 키워(최대 1.7배) PC 모니터에서 버튼이 과하게 커지지 않는다. 작은 폰은 0.85배까지 줄인다. 창 크기나 화면 방향이 바뀌면 타이틀이 다시 배치된다
- **글자 크기 6단계**(제목·이름·버튼·본문·설명·안내)와 **버튼 역할**: 실행은 강조색으로 채우고(혼자 하기·방 만들기·다시 하기), 선택은 테두리로(무기·난이도), 보조는 테두리만(◀ ▶·뒤로·기록 저장). 타이틀은 일러스트 카드와 같은 폭의 메뉴 열을 한 덩어리로 가운데 정렬한다
- **스킨 3종**: 파티마(기본, 강조색이 고른 파티마의 색을 따라감), 미라주(금색과 검정), 네온(하늘색과 남색). 타이틀 우상단 버튼으로 돌리고 기기에 저장된다
- **피격 표시**: 맞으면 캐릭터가 깜빡이고 피해량이 떠오르며, 내가 맞았으면 화면 가장자리가 붉게 번진다
- HUD는 초상과 HP 바만 그려 화면을 가리지 않는다. 진단 정보는 `?debug=1`일 때만 보인다
- PWA. 매니페스트와 서비스워커로 오프라인 캐시와 자동 업데이트, 타이틀에 설치 버튼
- 효과음은 Web Audio로 합성한다. 에셋 파일 0개, 타이틀에서 음소거 토글
- 아레나에 들어가면 Wake Lock으로 화면 꺼짐을 막고, 세로 화면이면 회전 안내를 덮는다
- 처음 3초 프레임을 재서 느린 기기는 파티클을 줄인다

## 결과와 전적

호스트 권위로 집계한 통계를 스냅샷에 실어 양쪽이 같은 표를 본다. 명중률, 발사와 명중, 가한 피해와 받은 피해, 대시, 협동은 처치와 다운, 경기 시간과 코어 HP다.

결과 화면에서 한쪽이 다시 하기를 누르면 상대에게 신호가 가고 **양쪽이 모두 누르면 함께** 새 판을 시작한다. 혼자 눌러 빈 아레나에서 기다리는 일이 없다.

기기 로컬 전적은 브라우저 저장소에만 남는다. 공개 랭킹은 없다.

결과 화면의 **경기 기록 저장**은 그 경기의 진단 기록을 JSON으로 내려받는다. 0.5초 간격의 RTT, 호스트 진행 속도, 버려진 입력, 보정량, 양쪽 파티마와 체력, **무엇에 얼마나 맞았는지**(상대 사격·척후병 접촉·포수 사격 등), 내 이동 입력과 입력 상태(키보드 / 포커스 없음 / 터치)가 들어 있다. 혼자 하기면 난이도도 적힌다. 두 기기의 파일을 맞춰 보면 동기화가 어긋난 지점을 찾을 수 있다.

## 테스트

```bash
npm run check:sim
```

화면 없이 순수 로직만 돌려 규칙을 숫자로 확인한다. 현재 53개 항목이 1초 안에 통과한다. 같은 시드를 주면 항상 같은 결과가 나온다.

폰에서 무엇을 어떻게 확인하고 합격 기준이 무엇인지는 [실기 테스트 가이드](docs/08.실기_테스트_가이드.md)에 체크리스트로 있다.

문서에 손으로 적은 숫자는 `npm run check:docs`가 코드와 대조한다. 파일 줄 수와 검사 개수를 세 번 틀린 뒤에 만들었다.

| URL 옵션 | 효과 |
|----------|------|
| `?debug=1` | 진단 줄 표시, `window.__game`과 `window.__link` 노출 |
| `?lag=120&jitter=30&loss=10` | 지연·흔들림·손실 주입. 손실은 `input` 채널에만 적용 |
| `?join=123456` | 해당 방으로 바로 참가 |

`?debug=1`이면 `window.__link.debugDrop('transport')`로 재접속 흐름을 즉시 재현할 수 있다.

## 호스팅 (노트북 없이 폰끼리)

시그널링 서버는 방 코드와 연결 협상만 중개하므로 무료 호스팅으로 충분하다. 실제 게임 데이터는 여전히 두 기기가 직접 주고받는다.

1. **시그널링 → Render**: [render.yaml](render.yaml) 블루프린트. 대시보드에서 New → Blueprint → 이 저장소 → Apply. 배포 후 `/healthz`가 `{"ok":true}`를 주면 완료. 클라이언트에는 `wss://<이름>.onrender.com`을 `VITE_SIGNALING_URL`로 준다. 무료 플랜은 15분 유휴 후 잠들어 첫 접속이 30~60초 느릴 수 있다
2. **웹 앱 → GitHub Pages** (선택): Settings → Pages → Source를 "GitHub Actions"로, Variables에 `SIGNALING_URL` 추가, Actions 탭에서 배포 워크플로 수동 실행. 서브 경로 배포는 `VITE_BASE`를 쓴다. 저장소에 없는 초상 이미지는 Pages에도 없다
3. 개발 서버를 쓰면서 시그널링만 호스팅된 것을 쓰려면 `apps/web/.env`에 `VITE_SIGNALING_URL=wss://...`

아직 실제 배포는 하지 않았다. 계정이 필요한 작업이다.

|------|------|----------------------|

| 시그널링 확장성 | 방을 메모리에 보관 | 인스턴스 1개 기준. 늘리려면 공유 저장소가 필요하다 |

## 라이선스와 권리

코드는 개인 학습·취미 목적으로 공개한다. 『파이브 스타 스토리』의 캐릭터·설정·일러스트에 대한 모든 권리는 나가노 마모루와 권리자에게 있다. 원작 일러스트는 이 저장소에 포함되어 있지 않다.
