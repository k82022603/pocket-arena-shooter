# 테스트 방식과 "헤드리스"란

- **작성일**: 2026-09-19

## 1. 헤드리스(headless)란
"머리(head) 없음" = **화면(UI)과 입력 장치 없이 프로그램의 논리만 실행**하는 방식이다. 브라우저 창도, 캔버스도, 키보드도 없이 코드가 계산만 한다.

이 프로젝트에서 헤드리스로 돌릴 수 있는 이유는 게임 규칙(이동·사격·판정·웨이브·픽업·봇)이 `apps/web/src/sim/` 안에 **Phaser나 브라우저에 의존하지 않는 순수 TypeScript**로 분리되어 있기 때문이다. 같은 코드가 세 곳에서 그대로 실행된다.

| 실행 환경 | 무엇이 도는가 | 화면 |
|-----------|---------------|------|
| 폰/노트북 브라우저 (실제 플레이) | sim + Phaser 렌더링 + 네트워크 | 있음 |
| Claude의 내장 브라우저 (자동 조작 검증) | 위와 동일한 게임을 코드로 클릭·키 입력 | 있음 (스크린샷으로 확인) |
| `npm run check:sim` (헤드리스) | sim만 Node.js에서 실행 | 없음 |

**모바일은 헤드리스가 아니다.** 폰에서는 브라우저가 게임 전체(화면·터치·소리·네트워크)를 정상적으로 실행한다. 헤드리스는 개발 중 규칙을 빠르게 확인하는 도구일 뿐이다.

## 2. 왜 헤드리스 검사를 쓰나
- 1초 안에 수천 틱을 돌려 "산탄총이 5발 나가는가", "레이저가 관통하는가", "15초 후 픽업이 생기는가", "봇이 이기는가" 같은 규칙을 숫자로 확인한다.
- 화면을 보고 판단하는 것보다 빠르고, 같은 시드(`seed`)를 주면 매번 같은 결과가 나와 재현이 된다(시뮬레이션이 결정적).
- 실행: 
  ```bash
  npm run check:sim
  ```
  결과가 `PASS/FAIL`로 나오고 실패가 있으면 종료 코드 1. 검사 항목은 `scripts/sim-check.ts`에 있으며 규칙을 추가할 때 같이 늘린다.

## 3. 세 단계 테스트를 어떻게 나눠 쓰나
1. **헤드리스 (`check:sim`)** — 규칙·수치·직렬화(스냅샷 왕복)·봇 행동
2. **내장 브라우저 자동 조작** — 화면 배치, 연출, 조작 체계, 2탭 대전/재접속 같은 흐름
3. **실기기** — 터치 감각, 성능(fps), 소리, 카메라 QR, 실제 Wi‑Fi/셀룰러 지연

3단계의 구체적인 절차와 합격 기준은 [실기 테스트 가이드](실기_테스트_가이드.md)에 체크리스트로 정리해 두었다.

규칙 외에 두 가지를 더 화면 없이 잰다. `npm run check:balance`는 협동 방어전을 자동 플레이해 난이도를 숫자로 내고, `npm run check:docs`는 문서에 적힌 줄 수와 검사 개수가 코드와 맞는지 대조한다.

## 4. 모바일에서 플레이하기
1. 노트북에서 `npm run play` 실행 (Windows는 `play.cmd` 더블클릭). 서버 두 개가 뜨고 브라우저가 LAN 주소로 열린다
2. 터미널에 표시된 `게임 주소: http://<노트북 IP>:5173/` 를 **같은 Wi‑Fi에 있는 폰** 브라우저에서 연다 (Windows 방화벽이 물으면 허용)
3. 가로로 돌리면 게임 화면. 왼쪽 드래그 이동, 오른쪽 드래그 조준·발사, DASH 버튼
4. 두 대로 대전: 한쪽 "방 만들기" → 다른 폰이 QR을 기본 카메라로 찍어 링크로 열거나 코드 입력
5. 앱 안 카메라로 QR을 스캔하려면 https가 필요: `npm run dev:https`로 띄우고 `https://<노트북 IP>:5173` 접속(자체 서명 인증서 경고 1회 수락)
6. 홈 화면에 설치(PWA): Android Chrome은 타이틀의 "설치" 버튼 또는 메뉴 → 홈 화면에 추가, iOS Safari는 공유 → 홈 화면에 추가

주의: `localhost`는 그 기기 자신을 뜻하므로 폰에서는 반드시 노트북의 IP 주소를 써야 한다.
